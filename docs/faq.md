# 常见问题（完整版）

> 主 README 只保留最高频问题；这里是全部边角案例与真实翻车现场。

**Emby 里某番剧没封面/没简介？**
大概率是年份/季/集与 TMDB 不对齐导致匹配失败。用 Emby API 查该条目 `ProviderIds` 是否为空，对照 README 的三规则修正目录名与 `tvshow.nfo`，再对条目执行 `Refresh`（`ReplaceAllMetadata: true`）。

**qB 配置了 autorun 但不触发？**
检查配置段层级（qB 5.x 必须是顶层 `[AutoRun]` 段，写进 `[Preferences]` 下会静默失效）和占位符含义（`%L`=分类）。用 WebUI API `setPreferences` 写入并回读验证最可靠。

**改名工具对特殊字符报 `UnicodeEncodeError`？**
旧版工具以 GBK 打印预览，`½`/`♪` 等超集字符必崩（`PYTHONUTF8` 无效）。本脚本已内置占位符机制自动处理；改名工具 **v1.1** 起也把输出流降级为 `errors=replace`，两版都不会再崩。

**任务失败提示「改名工具无法识别工作区中的任何文件」？**
原始文件名是工具解析不了的形态，两类都已自动处理：
- **英文点分(scene)发布名**（`Now.That.I...Girls.S01E01.1080p....MSubs-ToonsHub.mkv`：组名在结尾、标题点分）：改名前就预改写为 `[组] 标题 - SxxEyy.ext`（**季号保留**，工具认 `- S02E05`），可直接识别（该形态改名工具 **v1.1** 起也已原生支持）；
- **其他不可解析形态**：按 qB 任务名预改写为 `[组] 标题 - NN.ext` 后自动重试一次。

若任务里有多个视频文件（无法逐集对号）则不救援，工作区保留在 `_残留待处理\_改名失败_*` 供人工处理。

**集号被改成奇怪的数字（例如明明是第 1 集，却入库成 `S01E08`）？**
旧版改名工具（**v1.1 及以前**）的解析 bug：源文件 `[Sakurato] …Yubiwa [01v2][AVC-8bit 1080P AAC][CHS].mp4` 的集号 `[01v2]`（方括号 + 版本号）不被识别，工具落到横杠模式后，把 `[AVC-8bit…]` 里的 `-8` 当成了集号，产出 `… 01v2AVC - S01E08 - Sakurato.mp4`（集号错、标题还残留 `01v2AVC`）。现在有**两道防线**：

- **改名工具 v1.2**（源头修复）：方括号模式支持 `[01v2]`/`[05V2]`，横杠模式加 `(?![A-Za-z0-9])` 防误吞，`8bit`/`1080p`/`x264` 不再被当集号；
- **改名工具 v1.3**（源头修复第二例）：标题内连字编号 `U-17` 的 `-17` 不再抢在独立集号 ` - 03` 之前命中；
- **脚本 v25~v27 集号守卫**：任务名集号认**方括号形态**（`[01v2]` → E01）与**独立横杠形态**（`- 03` → E03），即便仍在用旧版工具，也会自动纠回正确集号并留一条 `集号按 qB 任务名(Exx) 校正` 的 WARN。

若历史文件已经以错误集号入库，把库内文件名改成正确集号、删掉 Emby 造的占位分集 `.nfo`，再对剧集条目执行一次 `Refresh` 即可恢复。

**英文标题的番搜不到目标目录、进了 `待归档\`？**
点分名发布的标题通常是**英文**，Bangumi 侧容易「有结果但置信度不足」。脚本用 TMDB 反查兜底：先按英文名查一次（TMDB 对英文查询返回**原始语种名**），再用该名查第二次拿**中文名**，然后对齐库内既有目录或新建 `<中文名> (<TMDB 首播年>)`。若该番属于另一个媒体库（如 NSFW 库），在那个库内**预建同名目录**（可放含 `<tmdbid>` 的 `tvshow.nfo`）即可——脚本会自动对齐过去，而不是新建分叉目录。

**新一季是独立 Bangumi 条目（ani-rss 按 S01 编号），但 TMDB 是合并单季，集号对不上？**
在 `SEASON_OVERRIDES` 加一条：`{"show": [...], "file": [...], "season": N}`；若该季在 TMDB 上续排在超长 Season 里（如第 4 期续排进 S1 第 51 集起），再加 `"ep_offset": 50`。`file` 关键字要能命中原始文件名或 qB 任务名。

**明明 TMDB 只有一季，脚本却建了 `Season 2`（Emby 里该季分集全是空壳标题）？**
典型的**本地回声**陷阱：Emby 的季列表由本地目录扫描而来，「`Season 2` 存在」并不等于 TMDB 有第 2 季。当 ani-rss 按「第 2 期」给 `Season 2`、而 TMDB 把它建成**独立新条目**（该条目自身只有 S1）时就会中招（实测《魔法少女育成计划 restart》）。v26 起由 **C′ 本地回声保护**自动归并回 `Season 1` 并迁移既有文件；若某次判定有误，把 `TMDB_ECHO_GUARD = False` 可完全关闭该纠正。

**目录名和 Emby 里显示的剧名对不上？**
Emby 展示的剧名来自 TMDB 元数据，而 Bangumi 与 TMDB 的译名可能不同（实测：Bangumi「归还者的魔法要特别」vs TMDB/Emby「重生者的魔法一定要特别」）。v26 起新建目录时基础名**优先取 TMDB 规范名**（与 Emby 显示名同源），Bangumi 名仅作回退。既有目录若已错名，改目录名即可，Emby 重新扫描后会正常显示。

**本机访问 TMDB 官网返回 403、API 返回 401？**
403 多半是**伪装浏览器 UA 触发了 Cloudflare 反爬**——本项目请求官网时**不带浏览器 UA**（只用 `Accept-Language`），实测直通 200；401 是**缺密钥的鉴权失败而非网络封锁**，填上 `QBR_TMDB_APIKEY` 即可。密钥只从环境变量读取，切勿写死在文件里（脚本对错误日志里的 key 做了打码）。

**qB 弹「I/O 错误(file_open)」通知？**
脚本版本 < v32 的时序问题（先搬移文件、末尾才删种，窗口期 qB 对被移走的文件报错）。升级到 v32+：处理开始即前置释放种子任务（`deleteFiles=false` 留文件），彻底消除弹窗。详见 [CHANGELOG v32](CHANGELOG.md)。
